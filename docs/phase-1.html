453a57222:03 IST

Add the /api/ai serverless scaffold

Input

the design's rule that the Meta key must stay on a server, never in the browser.

Output

20 files: a small Meta client (chat, speech-to-text, images; retries on 429/503; the key is redacted from every error), rate limits, size caps, a response cache, five stub endpoints under /api/ai/* that answer 501 until they are built, a local runner (npm run dev:api), vercel.json, .env.example. 35 new tests, 877 total, all pass. Tested only against mocked responses because there was no key yet.

In plain terms

the plumbing. When a model call is wired in, it already has safe limits and a safe place for the key.

d7ddeff22:20 IST

Add the level spec, its clamp and schema, the verifier and a pure floor builder

Input

the design's LevelSpec: one description of a level (place, layout, size, contract, twists, enemies, hazards, loot, seed) that a model can write and the game can build.

Output

levelspec.ts (the type, a JSON schema shaped for model output, a clamp that never throws and reports what it changed), verify.ts (three layers: the spec, the grid, the placement, each with named failure codes), floorbuild.ts (builds a floor with the game's own generators, same spec and seed give the same floor). 43 new tests, 920 total, pass. Findings that corrected the design: a literal "no laser blocks the way" fails about 70% of floors, so one crossing is allowed; the game caps guards at 4, not 6; tiny 6 x 5 floors rarely pass the exit-distance check.

In plain terms

the part that lets an AI describe a level and lets us check, without playing it, that it is finishable.

Record the spike results and revise the photo-to-map and voice designs

Input

the spike results.

Output

docs/SPIKES.md. Key results: the key works and lists every model; Spark returns valid JSON for a schema (3 to 4 s); SAM cannot segment "wall" or "door" (zero matches), but Spark finds the room boxes and SAM turns each box into a pixel-accurate mask, which a grid conversion turns into rooms with walls between them; the voice trip (speech to transcript to order) is exact but takes 4.2 to 4.5 s. Plan changes: photo to map keeps its go with a new pipeline (about 9 s), and obvious voice commands get a local fast path. we found out early what works and what doesn't, and the plan now reflects it.
